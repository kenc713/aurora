# 02. User Story

## 使い方（テンプレート）
ユーザーとして、[誰] は [何をしたい]。なぜなら、[価値/理由] を得たいからだ。
受け入れ条件:
- [条件1]
- [条件2]

---

## 機能別ユーザーストーリー

### 天気予報
- ユーザーとして、新卒会社員は出社準備の前に1〜3時間単位の天気を知りたい。なぜなら、服装や傘の準備を最適化したいからだ。
  - 受け入れ条件:
    - 現在地/指定地域の直近の降水確率・気温・体感温度が見える。
    - 朝のダッシュボードで一目で確認できる。

### バスの時刻表・運行状況
- ユーザーとして、新卒会社員はよく使うバス停の次発・遅延情報を知りたい。なぜなら、出発時刻を最適化し遅刻を避けたいからだ。
  - 受け入れ条件:
    - 出発地点のバス停と到着地点のバス停を登録することで、両地点を通るバスの運行状況を確認できる。
    - 遅延/運休がある場合は強調表示される。
    - 朝のダッシュボードで選択した登録バス停間のバスの運行状況を表示できる。

### タスクの分析・統計
- ユーザーとして、新卒会社員は期間ごとの完了したタスク数や作成したタスク数を知りたい。なぜなら、習慣化と改善に役立てたいからだ。
  - 受け入れ条件:
    - 週/月ごとの完了率が可視化される
    - 自己ベンチマーク（直近4週比較）が見える

### タスク管理（やるべき/やりたいの分離）
- ユーザーとして、新卒会社員は「やるべき」と「やりたい」を分けてタスクを管理したい。なぜなら、モチベーションを保ちつつ必須タスクを確実にこなしたいからだ。
  - 受け入れ条件:
    - タスクは種類（やるべき/やりたい）で作成・編集・フィルタできる
    - 期日・優先度・ラベルを設定できる
    - 今日ビューで本日やるべきタスクが一覧できる
    - ダッシュボードに今日の重要タスクが表示される

### リーディングリスト
- ユーザーとして、新卒会社員は気になる技術記事を後で読む用に保存したい。なぜなら、出社前の短時間で全て読めないからだ。
  - 受け入れ条件:
    - URL保存とラベル付けができる
    - 未読/既読でフィルタできる

### AI要約（自動/キュー）
- ユーザーとして、新卒会社員は保存した記事の要約を短時間で把握したい。なぜなら、限られた朝の時間で学びの効率を上げたいからだ。
  - 受け入れ条件:
    - 要約キューに追加でき、バックグラウンドで処理される
    - 要約は要点/所要時間/推奨優先度を含む

### ダッシュボード（朝の一目確認）
- ユーザーとして、新卒会社員は朝に重要情報だけを一画面で確認したい。なぜなら、複数アプリを開く時間がないからだ。
  - 受け入れ条件:
    - 天気/バス/今日のタスク/新規要約のカードが表示される
    - カードは非表示設定・並び替えができる

---

## 実装順（機能単位の進め方）
1) ダッシュボード（枠のみ・ダミーデータ）
2) タスク → 天気 → バス → リーディング → AI要約 の順にカードを実データ化
3) 分析/統計の追加、設定（カード並び替え/非表示）

## 非機能（関連要件）
- モバイル/デスクトップのレスポンシブ対応
- ローディング・エラー表示の一貫性
- 機能フラグで未完成機能を隠す（trunk-basedを支援）
